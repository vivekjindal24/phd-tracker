     Design highlights

     - Schema: one Neon DB, single core schema owned by the API (export is
       stateless, reads via internal REST — no cross-schema writes by
       construction). All tables: id uuid PK, created_at/updated_at, deleted_at
       (soft delete only). TEXT + CHECK constraints, not native enums.
     - Audit: one core.audit_log table with full prev/data JSONB snapshots +
       from_state/to_state per transition — replaces Frappe's per-entity version
       docs; written by an explicit write_audit() helper after every mutation
       (no ORM event magic).
     - Search: pg_trgm GIN indexes + ILIKE (partial match on
       PHD-CS-2024...-style IDs); grouped results, scoped by the same ownership
       filter as everything else.
     - RBAC: matrix as data in rbac.py; route-level require_roles(...) gate +
       row-level scope()/get_or_403() helpers so no router can skip the
       ownership filter. Closes the v1 gap (scholar sees only own records) by
       construction.
     - Workflow: TRANSITIONS = {(state, action): (roles, new_state)} dict;
       apply_action() mutates state, sets/clears approved_on on approve, writes
       audit row. Duplicate APR: partial unique index (scholar_id, report_year, 
       period) WHERE deleted_at IS NULL → IntegrityError → 409. UGC cap: count
       check on supervisor assignment + designation cap (8/6/4) validated.
     - Tokens: access token in memory (module var in api.ts); refresh in
       localStorage; single-refresh-on-401 replay in the fetch wrapper. Upgrade
       path (Next route-handler proxy with httpOnly cookies) documented, not
       built.
